# geoknn — 空间最近邻查询模块

TerraSight 地理空间引擎的查询服务使用的内存最近邻库。要素由上层加载后
交给本模块，常驻内存，模块本身不做持久化、不监听端口、无外部依赖
（仅 Go 标准库）。

## 功能

- 要素：全局唯一编号 + 图层 + WKT 几何（`POINT` / `LINESTRING` / `POLYGON`
  及对应 `MULTI` 类型，WGS84 经纬度，经度在前，面可带洞）。
- 编辑：批量导入（每批 ≤ 5000，整批原子生效）、删除、替换几何。
- 查询：给定点 + 数量 k（1..100）+ 可选最大距离（1..50000 米，含等于）+
  可选图层范围，返回按（距离，编号字典序）排序的最近 k 个要素。
- 距离模型：半径 6371008.8 米的球体；相邻顶点取较短大圆弧（跨 180° 经线
  亦然）；经度 ±180 相同；纬度 ±90 时经度无关；面取环所围较小一侧，
  面 = 外环 − 洞；点在面内/边界上距离为 0，落在洞里按到洞边界算。
- 并发：查询与编辑可并发（`sync.RWMutex`），每次查询看到某一时刻的完整
  数据，一批导入要么全看到要么全看不到。

## API

```go
e := geoknn.NewEngine()
err := e.Import([]geoknn.Feature{{ID: "w1", Layer: "well", WKT: "POINT(116.4 39.9)"}})
err  = e.ReplaceGeometry("w1", "POINT(116.4 39.91)")
err  = e.Delete("w1")            // 不存在返回 geoknn.ErrNotFound
res, err := e.Query(geoknn.Query{
    Lon: 116.4, Lat: 39.9, K: 20,
    MaxDistance: 5000,            // 0 表示不限
    Layers:      []string{"well"}, // 空表示全部图层
})
```

导入/替换的校验：WKT 解析失败、空几何、坐标越界、环不闭合、顶点不够
（线 < 2、环 < 3 个不同顶点）、相邻顶点对跖、编号重复。批量导入任一要素
不合法则整批不生效，返回 `*geoknn.ImportError`（含批内序号与原因）。
规模上限：50 图层 / 50 万要素 / 500 万顶点，超限报错。

## 设计要点

- 坐标统一转为三维单位向量，所有计算在球面上进行，天然处理 180° 经线
  与两极；夹角用 `atan2(|a×b|, a·b)`，近距离也有亚毫米精度。
- 每个要素预计算包围球冠（中心 + 角半径）。查询用余弦展开的剪枝条件
  `cos∠(p,c) < cos(θ+r)` 做 O(1) 过滤，配合大小为 k 的最大堆；热数据
  连续存储（SoA），全量扫描 50 万要素约 1-2 毫秒。角半径 ≥ π/2 的要素
  球冠不变式不成立，不参与剪枝。
- 点在环内用射线法：取环顶点合向量方向的对跖点（可证在较小区域之外）
  作参考点，统计较短弧与环边的相交次数；交点判定含"同一交点"校验，
  避免球面上两大圆有两个对跖交点导致的误判。
- 删除/替换为 O(1)（槽位交换移除），编辑后下一次查询立即可见。

## 测试

```bash
go test ./geoknn/ -short          # 快速：正确性 + 随机对比 + 并发（-race 建议）
go test ./geoknn/ -race -short
go test ./geoknn/ -run TestPerfFullScale -v   # 满规模性能（50 万要素）
go test ./geoknn/ -run TestPerfHeavyBatch -v  # 5000 要素/50 万顶点导入
```

测试内容：可手算场景（赤道两点、同经线两点、极点、对跖点等）；随机数据
（含跨 180° 经线的线和面、包极点的面、带洞的面、边界上的查询点、1 米
以内距离、部分图层）与逐个要素算距离的结果对比，随机穿插导入/删除/
替换后重新对比；包围球冠剪枝不变式；并发交错下的 -race 检查。

满规模实测（Apple Silicon）：导入单批最大 22ms；查询平均 1.7ms、
最慢 8.3ms；堆内存约 707MB。
